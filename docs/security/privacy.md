# 프라이버시

!!! spec "규격 · 개정판"
    IEEE 802.15.4 MAC 주소 체계(확장·짧은 주소), 보안 부계층 · IEEE 802.15.4z-2020 측거 IE · FiRa 데이터 프라이버시 기능 · iOS Nearby Interaction, Android UWB 권한 모델

!!! basic "한눈에 보기"
    보안이 "남이 속이지 못하게" 하는 것이라면, 프라이버시는 "남이 엿보지 못하게" 하는 것입니다. UWB는 정밀한 위치 기술이라 엿보는 쪽의 이득도 큽니다.

    걱정해야 할 것은 세 가지입니다.

    1. **추적** — 내 휴대폰이 보내는 UWB·BLE 신호의 고정 식별자로, 매장·거리의 수신기가 나를 따라다님
    2. **위치 노출** — 측거 결과(거리·각도)가 앱이나 서버로 넘어가 내 위치가 기록됨
    3. **엿듣기** — 측거 메시지에 실린 정보(기기 종류, 서비스 ID)를 제3자가 수신

    UWB 생태계의 기본 원칙은 **평소에는 조용히, 필요할 때만 짧게** 송신하고, 식별자는 **자주 바꾸고**, 측거 결과는 **사용자 동의 아래**에서만 앱에 주는 것입니다.

## 식별자와 추적 { .l2 }

| 정보 | 노출 위치 | 완화 |
|---|---|---|
| MAC 확장 주소 (64비트) | 802.15.4 MAC 헤더 | 측거 세션에서는 짧은 주소 사용, 세션마다 새로 할당 |
| 짧은 주소 (16비트) | MAC 헤더 | 세션 단위로 무작위 할당 |
| 세션 ID | 측거 IE, 제어 메시지 | 세션마다 새로 생성 |
| BLE 광고 주소 | 측거 전 발견 단계 | BLE 무작위 주소(주기적 변경) |
| 서비스·기기 정보 | 광고 데이터, 제어 메시지 | 암호화, 최소 정보만 광고 |

SP3 측거 프레임처럼 **페이로드가 없는 프레임**은 엿들을 정보가 거의 없습니다. 측거 제어 데이터는 데이터 보호 키로 암호화하고, FiRa는 주소·식별자 노출을 줄이는 프라이버시 키를 따로 둡니다([FiRa 보안 구조](fira-security.md)).

## 수동 추적이 어려운 이유와 남는 위험 { .l2 }

UWB는 측거가 필요할 때만 수 ms 단위로 짧게 송신하므로, BLE처럼 상시 광고하는 기술보다 수동 추적이 어렵습니다. 그러나 다음은 여전히 위험 요인입니다.

- **측거 시작 전 BLE 단계**: 발견과 파라미터 교환은 BLE로 하므로 BLE의 프라이버시 수준을 그대로 물려받습니다.
- **고정 인프라의 측위**: 건물에 설치된 앵커가 내 기기와 측거하면, 인프라 운영자는 내 위치를 정밀하게 압니다. TDoA 방식 중 **DL-TDoA**는 기기가 수신만 하므로 위치가 기기 안에서만 계산되고, **UL-TDoA**는 기기가 송신해 인프라가 위치를 압니다([TDoA](../ranging/tdoa.md)).
- **물리층 지문**: 안테나·클럭 특성으로 기기를 구분하는 연구가 있습니다. 식별자를 바꿔도 남을 수 있는 위험입니다.

## 운영체제의 권한 모델 { .l2 }

| 플랫폼 | 방식 |
|---|---|
| iOS | Nearby Interaction 세션마다 사용자 허가. 상대 기기와 앱이 토큰을 교환해야 측거 가능. 기기 간 측거 결과는 앱에만 전달 |
| Android | UWB 측거 권한(근처 기기 권한 그룹), 시스템 UWB 서비스가 세션 관리 |

자세한 API는 [스마트폰 API](../ecosystem/smartphone-api.md)에 있습니다.

??? expert "전문가 노트 — DL-TDoA와 프라이버시 설계"
    측위 시스템을 설계할 때 "누가 위치를 계산하나"는 프라이버시 구조를 결정합니다.

    - **TWR**: 양쪽이 모두 거리를 압니다. 인프라와 TWR을 하면 인프라도 위치를 압니다.
    - **UL-TDoA**: 태그가 블링크를 보내고 인프라가 위치를 계산합니다. 자산 추적에 적합하지만 개인 기기에는 프라이버시 부담이 큽니다.
    - **DL-TDoA**: 앵커들이 서로 메시지를 주고받고 기기는 **듣기만** 해서 스스로 위치를 계산합니다. GPS와 같은 구조로, 인원 제한이 없고 기기가 송신하지 않아 인프라가 기기를 알 수 없습니다.

    FiRa가 DL-TDoA를 실내 내비게이션용으로 정의한 데에는 확장성뿐 아니라 이 프라이버시 특성도 중요한 이유였습니다([실내 측위와 내비게이션](../apps/indoor-navigation.md)).

    다만 DL-TDoA에서도 **측거 전 단계**(앱이 앵커 정보를 내려받는 과정)나 위치 결과를 서버로 보내는 앱 동작이 프라이버시를 깰 수 있으므로, 전체 데이터 흐름을 함께 검토해야 합니다.
