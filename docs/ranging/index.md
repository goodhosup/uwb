# 측거와 측위

이 섹션은 이 핸드북의 중심입니다. UWB가 **두 기기 사이의 거리**(측거, ranging)를 어떻게 재고, 여러 거리·시각 차·각도를 모아 **위치**(측위, positioning)를 어떻게 계산하는지 다룹니다. 앞 섹션의 [대역폭과 시간 분해능](../basics/bandwidth-resolution.md)이 "왜 정밀하게 잴 수 있나"였다면, 여기서는 "실제로 어떤 순서로 메시지를 주고받고, 어떤 식으로 계산하나"를 봅니다.

| 페이지 | 핵심 질문 |
|---|---|
| [ToF 측거 원리](tof.md) | 시계가 서로 맞지 않는 두 기기가 어떻게 ns 단위 비행 시간을 재나? |
| [SS-TWR](ss-twr.md) | 한 번 왕복으로 거리를 재면 왜 클럭 오차가 m 단위로 커지나? |
| [DS-TWR](ds-twr.md) | 메시지를 하나 더 보내면 클럭 오차가 어떻게 거의 사라지나? |
| [TDoA (UL·DL)](tdoa.md) | 태그가 응답하지 않고도 위치를 구하는 방법은? 앵커 동기는 왜 필요한가? |
| [AoA와 PDoA](aoa-pdoa.md) | 안테나 두 개의 위상 차로 방향을 어떻게 알아내나? 왜 간격이 λ/2 이하여야 하나? |
| [위치 추정 알고리즘](positioning.md) | 거리·거리 차·각도로 좌표를 어떻게 풀고, 앵커 배치는 왜 중요한가? |
| [오차 요인과 보정](errors-calibration.md) | 안테나 지연, 클럭, NLoS, 수신 레벨 편향은 각각 얼마나, 어떻게 보정하나? |
| [성능 지표](metrics.md) | "정확도 10 cm"라는 말은 정확히 무엇을 뜻하나? 무엇을 함께 봐야 하나? |

!!! basic "이 섹션을 읽는 순서"
    1. **ToF → SS-TWR → DS-TWR** 순서로 읽으면 "시계 오차를 어떻게 없애나"라는 한 줄기 이야기가 됩니다.
    2. **TDoA, AoA/PDoA**는 같은 문제를 다른 방향(태그가 송신만 하거나 듣기만 하는 방식, 각도로 재는 방식)에서 푸는 방법입니다.
    3. **위치 추정 → 오차와 보정 → 성능 지표**는 측정값을 실제 서비스 품질로 바꾸는 과정입니다. 측거 메시지를 어떤 시간 슬롯에 넣는지는 [측거 라운드 구조](../mac/ranging-rounds.md)에서 다룹니다.
