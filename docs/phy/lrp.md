# LRP PHY

!!! spec "규격 · 개정판"
    IEEE 802.15.4-2020 LRP UWB PHY 절 (기본·확장·장거리 모드, 프리앰블·SFD·PHR, LEIP) · 802.15.4z-2020 (LRP 확장: 이중 주파수 모드, EPC, 추가 SFD, 측거 표시) · 802.15.4ab (초안 기준, LRP 관련 내용은 논의 상황에 따라 다름)

!!! basic "한눈에 보기"
    **LRP(Low Rate Pulse repetition frequency) UWB**는 펄스를 **수 MHz 이하로 드물게** 보내는 UWB PHY입니다. HRP가 약한 펄스를 수천 개 모아 상관으로 끌어올린다면, LRP는 펄스 하나하나에 에너지를 크게 싣고 수신기가 **"펄스가 있나 없나"**를 에너지로 판별합니다.

    규제는 평균 전력(1 ms 평균 PSD)을 묶기 때문에, 펄스 수를 줄이면 펄스 하나에 더 많은 에너지를 쓸 수 있습니다. 그 덕분에 LRP 수신기는 긴 상관기나 정밀한 위상 추적 없이 **단순하고 저전력**으로 만들 수 있습니다.

    비유하면 HRP는 속삭임을 녹음해 컴퓨터로 증폭하는 방식, LRP는 띄엄띄엄 크게 손뼉을 쳐서 귀로 듣는 방식입니다. 대신 LRP는 데이터율이 낮고, 오늘날 스마트폰·FiRa·CCC 생태계는 HRP를 쓰기 때문에 LRP 칩은 일부 벤더에 한정됩니다.

## 모드와 변조 { .l2 }

| 모드 | 변조 | 공칭 PRF | 데이터율 | 비고 |
|---|---|---|---|---|
| 기본 (base) | OOK, 맨체스터 부호 | 1 MHz | 1 Mb/s | 802.15.4 · 4z 공통 |
| 확장 (extended) | OOK + 길쌈 부호 | 1 MHz | 250 kb/s | 802.15.4 · 4z 공통 |
| 장거리 (long-range) | PPM | 2 MHz | 31.25 kb/s | 802.15.4 · 4z 공통 |
| 이중 주파수 계열 | PBFSK (두 중심 주파수 사이 전환) | 1–4 MHz | 수백 kb/s–수 Mb/s | 802.15.4z 추가 |
| EPC 계열 | PBFSK + 다치 PPM | 1–2 MHz | 3–10 Mb/s | 802.15.4z 추가, 가드 구간 포함 |

수치는 공개 서베이 자료(802.15.4·4z LRP 정리) 기준이며, 세부 조합은 규격 표를 확인해야 합니다. 802.15.4와 4z의 LRP는 기본·확장·장거리 모드에서 통신이 호환됩니다.

- **OOK(On-Off Keying)**: 펄스가 있으면 1, 없으면 0. 수신기는 에너지 검출기만 있으면 됩니다.
- **PPM(Pulse Position Modulation)**: 펄스를 어느 시간 칸에 놓느냐로 비트를 나타냅니다. 장거리 모드는 펄스 위치로 에너지를 집중해 감도를 높입니다.
- **PBFSK**: 펄스마다 두 중심 주파수 중 하나를 골라 정보를 싣는 방식으로, 4z에서 데이터율을 높이려고 추가되었습니다.

## 프레임과 측거 { .l2 }

LRP 프레임도 큰 틀은 HRP와 같습니다: **프리앰블 → SFD → PHR → 페이로드**, 그리고 선택적으로 **LEIP(Location Enhancing Information Postamble)**가 붙습니다.

| 필드 | LRP에서의 특징 |
|---|---|
| 프리앰블 | 모드의 PRF로 이어지는 펄스열 (장거리 모드는 여러 구간으로 구성) |
| SFD | 길이 16 코드, 802.15.4z가 32·64·128 추가 |
| PHR | 부호화 방식, 프레임 길이, SECDED, LEIP 길이·위치 등. 4z에서 예약 비트로 측거 프레임 표시 |
| LEIP | 프레임 뒤에 붙이는 펄스열로, 수신 측 도착 시각·위치 추정 정밀도를 높이는 용도 |

측거 관점에서 LRP의 장점은 펄스 사이 간격이 길어 **다중 경로 꼬리가 다음 펄스와 섞이지 않는다**는 점입니다. 펄스 하나의 첫 모서리를 에너지 검출로 바로 볼 수 있습니다. 반면 HRP의 STS 같은 "키 기반 펄스열 + 상관" 구조가 아니므로, 보안 측거는 다른 방식의 보호(예: 거리 경계 프로토콜 계열 설계)에 기대게 됩니다. 이 부분은 칩·규격 버전에 따라 다르므로 단정하지 않습니다.

??? expert "전문가 노트 — HRP와 LRP의 에너지 산수"
    1 ms 평균 PSD 한도가 같다면, 1 ms 안의 총에너지 \(E_{1ms}\)는 두 PHY가 같습니다. 펄스 수가 \(N_p\)면 펄스당 에너지는 \(E_{1ms}/N_p\)입니다.

    \[
    \frac{E_p^{\text{LRP}}}{E_p^{\text{HRP}}} = \frac{N_p^{\text{HRP}}}{N_p^{\text{LRP}}} \approx \frac{62.4\ \text{MHz}}{1\ \text{MHz}} \approx 18\ \text{dB}
    \]

    (평균 PRF 62.4 MHz와 1 MHz를 단순 비교한 경우.) HRP는 이 18 dB를 **상관 처리 이득**으로 되찾고, LRP는 처음부터 펄스 하나에 몰아 넣습니다. 이론적인 총에너지는 같지만 차이는 구현에서 납니다.

    - **수신기 복잡도**: LRP는 비동기 에너지 검출이 가능해 상관기·고속 ADC 부담이 작고 전력이 낮습니다.
    - **피크 한도**: 펄스당 에너지를 키우면 **피크 전력 한도**(50 MHz당 0 dBm 환산)에 먼저 걸립니다. LRP PRF를 무한정 낮출 수 없는 이유입니다.
    - **간섭 내성**: 에너지 검출은 협대역 간섭을 "펄스"로 오인하기 쉬워, HRP의 코드 상관보다 간섭 내성이 약할 수 있습니다.
    - **생태계**: 공개 자료에 따르면 LRP를 지원하는 상용 칩은 소수이고, 일부 벤더는 802.15.4z 이전부터 LRP 기반 측거를 구현했습니다. FiRa·CCC 인증 범위는 HRP입니다([칩셋 지형](../ecosystem/chipsets.md)).
